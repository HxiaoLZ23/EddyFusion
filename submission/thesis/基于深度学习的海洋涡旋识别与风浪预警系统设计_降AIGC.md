# 摘 要​

海表动力高度、海流、风场与波浪等资料多以 NetCDF 存储，来源多、网格大、时空维交织，业务系统要在可接受算力内完成涡旋判别与风浪研判仍面临工程压力。中尺度涡旋的传统在线识别往往逐步计算 Okubo–Weiss（OW）参数及流场梯度，链路长且阈值敏感。本文围绕上述约束，设计并实现一套基于 NetCDF 多源数据的中尺度涡旋识别与风浪异常分析系统。

涡旋模块以 OW 规则生成伪标签，用 YOLOv8-seg 学习涡旋空间形态，建立由海表动力高度（ADT）到场内实例掩膜的映射，以神经网络代理 OW 在线判别，在保留物理先验的同时压缩推理步骤。

风浪模块采用共享 LSTM 骨干上的双线性头，联合输出风速与有效波高一步预测；在逐步残差上构造无量纲异常指数并划分等级，于异常事件窗内截取区域平均观测风，与 IBTrACS 历史中心风过程经 z-score 后做 DTW 弱关联检索（该检索不参与 3σ 分级），为异常结果提供可核对的历史参照。

系统以 React 与 FastAPI 前后端分离部署，贯通 NetCDF 解析、时空裁剪、模型推理、曲线展示与报告导出。

关键词：NetCDF；海洋中尺度涡旋；弱监督学习；YOLOv8-seg；风浪异常分析；LSTM；DTW






# Abstract

With the advancement of ocean observation and reanalysis technologies, marine environmental data—such as sea surface dynamic height, ocean currents, wind fields, and waves—exhibit characteristics of multi-source heterogeneity, large data volumes, and complex spatiotemporal dimensions. Traditional methods for identifying mesoscale ocean eddies often rely on Okubo–Weiss (OW) dynamic parameter calculations and manual threshold setting. The online computation involves flow field gradient solving and the derivation of multiple physical quantities, resulting in high computational overhead that hinders intelligent analysis and operational applications. To address this problem, this paper designs and implements a mesoscale eddy identification and wind-wave anomaly analysis system based on NetCDF multi-source ocean data.

For eddy identification, a weakly supervised instance segmentation mechanism guided by OW dynamic rules is constructed. OW physical rules are used to generate pseudo-labels for eddies, while YOLOv8-seg learns the spatial distribution characteristics of eddies. An end-to-end mapping model from the sea surface dynamic height field to eddy instance masks is built, serving as a proxy for the traditional physical rule computation. This approach reduces the computational complexity of the online inference stage, thereby improving system deployment efficiency and real-time performance.

For wind-wave identification, a shared-encoder dual-head LSTM prediction model is constructed to jointly predict wind speed and significant wave height. Combined with the Dynamic Time Warping (DTW) algorithm, a weakly correlated retrieval mechanism for historical wind-wave processes is built to perform similar event matching and assist in traceability analysis of anomalous changes, enhancing the interpretability of wind-wave anomaly results.

In terms of system implementation, a front-end and back-end separation architecture is adopted using React and FastAPI, supporting functions such as NetCDF data parsing, spatiotemporal cropping, model inference, result visualization, and report export.

Keywords: NetCDF; mesoscale ocean eddies; weakly supervised learning; YOLOv8-seg; wind-wave anomaly analysis; LSTM; DTW



# 第1章 绪论

1.1 项目开发背景与意义

海洋在气候调节、资源开发、航运与灾害预警等环节作用突出。卫星遥感、浮标、再分析与数值模式持续产出环境场数据，变量多、序列长、网格规模大，为智能分析提供了数据条件，也把解析与工程化门槛一并抬高。

业务侧常见载体是 NetCDF：时间、经纬度与多变量可同文件描述，跨平台交换方便。难点在于各产品变量命名、网格与时间步不一致，解析与对齐耗工；多变量、多尺度协同时，纯人工流程难以稳定复现。建设统一的数据接入与推理展示平台，是海洋信息化中的现实需求。

中尺度涡旋尺度约数十至数百千米，生命史可达数周至数月，参与热量与物质输运及海气交换[1,4]。快速、可靠地圈定涡旋范围，长期是遥感与信息处理的关注点。

风浪突变则直接牵动航运、工程与渔业安全；极端过程往往伴随高后果风险。统计或经验判读对序列依赖挖掘不足，对趋势与异常的联动解释偏弱[14-17]。把预测、分级预警与历史过程对照放在同一套系统里，具有明确的应用价值。

深度学习在检测、分割与时序建模上已有成熟实践[5-9]，但海洋场数据并非自然图像：格式异构、维结构特殊，通用模型往往不能“即插即用”；分辨率与时间步差异也抬高集成成本。

现有工作仍有三处缺口：其一，OW 等动力学规则在线计算链长、阈值敏感；其二，监督式涡旋分割依赖昂贵的人工边界标注；其三，不少研究停在离线精度对比，对数据接入、在线推理、异常解释与业务闭环着墨不足。

本文在多维海洋观测数据上，把动力学先验与深度学习结合，实现涡旋识别、风浪预警、异常分析及可视化展示一体化的监测系统。

1.2 国内外系统平台现状分析

### 1.2.1 海洋中尺度涡旋识别研究现状

涡旋自动识别长期是遥感与海洋信息处理中的常规课题，因其直接关系到热量输运、物质交换与海气相互作用等过程的理解。

早期路线多依托海表高度异常、流场或海温场，用阈值分割、闭合等值线、区域生长等手段圈定候选区。Okubo–Weiss（OW）参数因具备动力学含义而被广泛采用[2,3]：比较旋转项与应变项相对强弱即可筛出涡旋区。

OW 在线实现要算地转流及其梯度，并推导相对涡度、应变率等中间量；区域大、序列长时算力开销明显。不同海区与季节的 OW 分布差异也会放大阈值敏感性，噪声背景下易出现虚警。

支持向量机、随机森林等机器学习方案提升了自动化程度，但特征多靠人工设计，对复杂空间结构的表达有限。

卷积网络、语义/实例分割网络已被用于涡旋场图识别，U-Net、Mask R-CNN、DeepLab、YOLO 等均可从环境场中学习空间模式[9,30,31]。实例分割能给出像素级轮廓，更适合边界不规则的中尺度涡旋[31,32]。

监督式深度模型往往依赖人工勾绘边界，而涡旋外缘存在主观性，大规模标注成本高。用 OW 等物理规则自动生成伪标签、再训练分割网络，成为弱监督方向：既保留动力学先验，又缩短在线推理链[33,34]。

归纳而言，动力学法可解释但算得慢；深度法表达力强但标注贵。以规则产监督、以网络做代理推理，是当前较务实的折中路线。

### 1.2.2 海洋风浪预测与异常分析研究现状

风浪预测关系监测、工程安全与灾害预警。传统路径大致分两类：统计回归靠历史样本拟合经验关系，实现轻、算得快，对强非线性过程刻画不足；数值模式求解流体方程，物理含义清楚，但建模与算力成本高。

RNN、LSTM、GRU 等序列模型已用于风速与波高预测，LSTM 的门控结构利于保留长程依赖，在海洋与气象时序任务中已有应用报道[28,35,36]。

异常识别与解释是另一条线。动态时间规整（DTW）可在时间轴上非线性对齐两条序列，常用于在历史库中找形态相近的过程，为当前异常提供参照；它通常不替代预测模型本身，而是站在解释层辅助研判。

现有工作多聚焦预测误差指标，对“异常为何出现、哪段历史过程最像”关注不足，业务侧仍需要把预测、分级与历史对照串成一条链。

### 1.2.3 海洋环境智能监测系统研究现状

国内外已建设多种海洋数据与预报平台，覆盖采集、存储、展示与数值预报等环节。国外数据共享与预报服务起步较早；国内近年的综合平台在数据管理与环境监测上也有进展。

多数系统仍以展示或数值预报为主，智能分析模块往往单点存在，识别、预测与异常解释很少在同一界面形成闭环。涡旋与风浪异常也常分属不同子系统，缺少协同。把多源接入、涡旋识别、风浪预测与异常解释、可视化导出放在同一套 Web 系统里，仍有工程与研究空间。

围绕 NetCDF 多源数据下的涡旋识别与风浪异常分析两类场景，本文完成如下工作：

# 第2章 系统开发关键技术

2.1 系统开发环境与基础框架

本系统后端与训练脚本统一用 Python 编写，配 PyTorch、科学计算库及 Web 服务组件。海洋场数据维数高、变量多、链路长，开发时既要保证训练吞吐，也要让解析与接口在长时间运行下保持稳定、便于扩展。

Python 在多维数组、深度学习与快速原型上的生态成熟，适合把 NetCDF 解析、YOLOv8-seg 训练与 FastAPI 服务放在同一语言栈内完成，迭代成本低于传统 C++/Java 全栈方案。

AI 部分采用 PyTorch[10]：动态图便于调整网络结构与做消融；GPU 张量运算与社区模型（含 Ultralytics YOLO）可直接复用，满足涡旋分割与 WindWaveLSTM 双任务训练需求。

2.2 NetCDF数据格式与多维海洋观测数据处理

观测与再分析产品来自卫星、浮标、模式输出等渠道，体量持续增长，结构也由平面栅格扩展为“时间×空间×变量”的多维数组。国际海洋与气象社区普遍用 NetCDF（Network Common Data Form）封装这类数据[12,13]。

单文件可同时记录 Time、Longitude、Latitude 及多环境变量，元数据自描述，便于跨平台交换。海表动力高度常组织为 Time×Latitude×Longitude；若并入风、流等多要素，则增加 Variable 维，本质是带坐标语义的多维数组。

本研究主要使用海面动力高度（ADT）、风速与有效波高。与自然图像相比，这类数据具有：维数多（时间、经纬度、变量并存）；变量间存在时空耦合；长序列可达 GB 级；不同产品命名与网格不一致（如 sla/adt/ssh 同指海表高度）；解析时需同时维护坐标与变量映射。

系统以 xarray 管理 NetCDF[11]。DataArray/Dataset 在存储数组的同时绑定维名与坐标，可用 `sel(time=…, lon=…)` 做切片，而不必手算下标；相对底层 netCDF4 接口，业务代码更短、更不易出错。

工程上 xarray 承担：读取维结构与属性；经 `config/nc_variable_map.yaml` 做变量别名统一；按用户给定时段与 bbox 裁剪；必要时重采样对齐不同分辨率；为 LSTM 构造 48 h 滑窗样本；配合 Dask 懒加载，按块读大文件以控制内存。上述流程把原始 NC 转为涡旋训练 BGR 张量与风浪 `(T,2)` 序列，供后续模块直接消费。

2.3 智能分析相关技术基础

涡旋识别看空间形态，风浪分析看时间演化，两类任务分别依赖实例分割与时序模型，下面分述原理。

### 2.3.1 实例分割技术概述

视觉任务里，检测输出框与类别；语义分割给每个像素打标签，但同类多个目标会连成一片；实例分割在像素级掩膜上区分个体，适合同场出现多个涡旋、且轮廓不规则的情形。

本系统选用 YOLOv8-seg：在 ADT/u/v 合成的场图上直接输出实例掩膜，与 OW 伪标签训练口径一致。

### 2.3.2 LSTM时间序列建模技术

风速、波高等变量相邻时刻相关。普通 RNN 传递隐状态即可建模序列，但长序列易梯度消失。LSTM 用输入门、遗忘门、输出门控制信息留存，更适合学习数小时至数十小时的依赖。

本系统 WindWaveLSTM 以 `(B,T,2)` 为输入（风速与波高两通道），共享 `nn.LSTM` 骨干，末步隐状态分别经两个线性头输出下一步风、浪预测，训练目标为 MSE。

### 2.3.3 动态时间规整技术

两条过程若起伏形态相近但快慢不同，固定对齐的欧氏距离会失真。DTW 在时间轴上允许局部拉伸，以最小累计代价对齐两段序列。

本系统把异常窗内区域平均观测风与 IBTrACS 候选台风中心风过程做 z-score 后算 DTW 距离，用于 Top-K 重排；该距离不参与风浪异常分级，仅作弱关联解释。

2.4 前后端可视化技术

Web 方案便于部署与演示：React 以组件拼装涡旋场图、风浪曲线与 Top-K 卡片；FastAPI 暴露 `/api/windwave/forecast`、`/api/eddy/...` 等 REST 接口，与 Python 推理代码同栈；曲线与统计图可用 Plotly 或 Matplotlib 生成后在前端展示。

React 负责交互界面，FastAPI 提供 REST 接口，Plotly/Matplotlib 承担曲线与场图绘制，三者共同支撑本系统的人机交互层。

2.5 本章小结

本章交代了 Python/PyTorch 开发栈、NetCDF 与 xarray 多维数据处理方式，以及实例分割、LSTM 与 DTW 的算法背景，并概述 React、FastAPI 与常用可视化库在 Web 监测系统中的角色，为后续需求与设计章节提供技术铺垫。


# 第3章 系统可行性分析与需求分析

本章在总体设计之前，把功能边界、运行方式与工程约束说清楚。算法论文常只报精度指标；本课题还要保证「上传 NC → 推理 → 展示 → 导出报告」能走通，故需同时写清业务需求与非功能需求。

系统链路覆盖 NetCDF 解析、YOLOv8-seg/LSTM 推理、IBTrACS 弱关联检索与 React 展示，模块间共享时空裁剪结果与结构化 JSON，设计时要预留接口版本与异步任务扩展。

3.1 系统可行性分析

### 3.1.1 技术可行性分析

**数据侧**：再分析与遥感产品多以 NetCDF 发布，维坐标完整；xarray、netCDF4 等库已能支撑切片、映射与缺失处理，数据获取与预处理有成熟工具链。

**算法侧**：分割与时序预测在海洋、气象领域均有先例；OW 等动力学诊断可为涡旋弱监督提供标签来源，与数据驱动模型可以分工：训练用物理规则，在线用轻量网络。

**工程侧**：React + FastAPI 前后端分离已是常见方案，REST 便于把 `web_api/routers` 与 `src/` 推理代码解耦，模块可独立升级。

### 3.1.2 经济可行性分析

数据以公开再分析与 IBTrACS 为主，无商业数据采购压力。PyTorch、Ultralytics、xarray 等均为开源栈，无授权费。算力大头在离线训练，在线以 CPU/GPU 推理与 I/O 为主，普通服务器即可承载演示与毕设级并发；模块边界清晰也有利于后续增量开发而非整库重写。

### 3.1.3 操作可行性分析

用户路径压缩为：上传 NC → 选时段/ROI/任务类型 → 查看场图或曲线 → 导出报告。预处理、OW 伪标签生成（离线）、LSTM 滑窗推理与 DTW Top-K 由后端自动完成。结果以场图、掩膜、四线曲线、异常色带与台风候选卡片呈现，适配教学演示与科研复核。

3.2 系统功能需求分析

### 3.2.1 多源海洋数据接入与标准化处理需求

（1）读取 NetCDF，识别 time/lat/lon 与 ADT、风、浪等变量；（2）按用户指定时段与 bbox 裁剪；（3）经变量映射表统一别名与单位；（4）缺失与异常值检查；（5）为涡旋生成 ADT/u/v 张量、为风浪生成区域平均 `(T,2)` 序列。对应 `POST /api/preprocess/subset` 与 `nc_variable_map.yaml`。

### 3.2.2 海洋中尺度涡旋智能识别需求

输出实例掩膜及数量、面积、中心位置等统计；区分气旋/反气旋（若标签可得）；支持时间轴切换帧、叠加场图与 MP4 动画；权重离线训练、在线仅 3 通道 ADT+u+v 推理。

### 3.2.3 风浪趋势预测与异常分析需求

（1）WindWaveLSTM 滑窗输出风/浪观测与预测四线；（2）逐步计算无量纲 `anomaly_index` 并标黄橙红等级；（3）异常事件窗内截取区域平均观测风，对 IBTrACS 候选做 DTW Top-K（弱关联，不参与分级）；（4）同屏展示曲线、等级与候选台风卡片。

### 3.2.4 可视化交互与分析报告需求

提供顶栏四入口（监测总览/涡旋/风浪/报告）、左配置-中可视化-右统计的 task 布局；支持图层切换、时间索引与 `POST /api/report/structured` 导出 Markdown/PDF 结构化报告。

3.3 系统非功能需求分析

### 3.3.1 大规模数据处理与资源控制需求

支持 GB 级 NC 的懒加载与 bbox/时间子集读取；控制峰值内存；推理阶段只加载当前窗而非全文件；长耗时任务可走异步 job 队列，避免阻塞 HTTP 连接。

### 3.3.2 离线训练与在线分析解耦需求

YOLO 与 LSTM 权重在 `outputs/` 离线训练，在线仅 `load_state_dict` + 滑窗/单帧推理；OW 伪标签生成放在预处理或训练流水线，运行期不重复全图 OW 计算。

### 3.3.3 模块化扩展与系统维护需求

`web_api/routers` 与 `src/eddy`、`src/anomaly` 分目录；OpenAPI 约定 JSON 字段；新增变量或模型时尽量只扩展映射表与单模块，避免改动 eval 指标链与 config `level` 语义。

3.4 本章小结

可行性上，公开数据与开源栈可支撑毕设级系统，操作路径已压缩为 Web 四步。功能上，明确接入、涡旋、风浪+DTW、报告四条主线。非功能上，强调懒加载、训练推理解耦与模块化接口，为第4章分层架构提供输入。

### 5.2.3 OW动力学规则伪标签生成

由于海洋中尺度涡旋真实标注数据获取成本较高，系统采用基于海洋动力学规则的自动标注方法构建训练数据集。

与依赖教师模型预测结果生成伪标签的模型驱动方法不同，本研究采用规则驱动伪标签生成策略，通过海洋动力学诊断量自动提取涡旋候选区域，为实例分割模型训练提供监督信号。

在训练数据构建阶段，系统首先读取海表地转流速场数据，并计算对应空间梯度信息。随后依据 Okubo–Weiss 判据构建动力学诊断参数场。

Okubo-Weiss 参数 W 是判别海洋中尺度涡旋区域的核心动力诊断量[2,3]，其定义为 ，其中法向应变率 ，剪切应变率 ，相对涡度 ，u、v 分别为地转流速的纬向与经向分量。在规则经纬度网格上，系统采用二阶中心差分法完成空间梯度计算，并结合经纬度距离修正提高计算精度。

获得 Okubo–Weiss 参数场后，系统采用分位数阈值法提取涡旋候选区域。具体地，以当前环境场中 OW 参数的第24百分位数作为阈值，当网格点满足对应条件时，将其判定为候选涡旋区域。相比固定经验阈值方法，分位数阈值能够在不同海域和不同季节条件下保持较好的适应能力。

候选区域生成后，系统进一步执行连通域分析、小区域过滤以及轮廓提取等后处理操作，最终得到满足实例分割训练要求的涡旋伪标签。

流程如下：

地转流速场(U,V) → 空间梯度计算 →计算相对涡度ζ → 计算应变率Sn、Ss → 计算OW参数 → 阈值判定 → 候选区域Mask → 连通域分析 → 面积过滤 → 轮廓提取 → 涡旋结果

生成的伪标签数据随后用于 YOLOv8-seg 模型训练，实现海洋中尺度涡旋自动识别模型的数据集构建。

5.3 海洋中尺度涡旋识别模块的实现

海洋中尺度涡旋识别是本系统的重要智能分析功能之一。传统基于阈值分割、区域生长或闭合等值线的方法通常依赖人工经验设置参数，在复杂海况背景下容易受到噪声干扰，难以准确描述涡旋边界形态。相比之下，实例分割模型能够同时完成目标定位与边界提取，更适用于海洋中尺度涡旋这类形态复杂目标的自动识别任务。

本研究采用 YOLOv8-seg 作为海洋中尺度涡旋识别核心模型。系统首先利用 OW 动力学规则自动构建训练标签，随后通过实例分割网络完成模型训练。在系统运行阶段，仅利用海表动力高度场构建模型输入，实现海洋中尺度涡旋区域的自动识别与边界提取。

### 5.3.1 YOLOv8-seg网络训练实现

完成训练数据集构建后，系统采用 YOLOv8-seg 作为海洋中尺度涡旋识别模型。YOLOv8-seg 是 Ultralytics 提出的轻量级实例分割网络，在目标检测框架基础上增加实例掩膜分支，能够同时输出目标位置与像素级分割结果，在保证识别精度的同时具备较好的推理效率。

网络整体结构主要由 Backbone、Neck 以及 Segmentation Head 三部分组成。其中，Backbone 负责提取输入环境场中的多尺度空间特征；Neck 负责不同尺度特征之间的信息融合；Segmentation Head 则完成目标检测与实例掩膜生成任务，输出目标类别、边界框以及对应实例分割结果。

对于海洋中尺度涡旋而言，其边界形态通常较为复杂，且不同尺度涡旋在空间分布上存在明显差异。因此，多尺度特征提取能力对于提高涡旋识别精度具有重要意义。YOLOv8-seg 通过特征金字塔结构实现不同尺度特征融合，能够较好地适应海洋环境场中的目标尺度变化。

考虑到海洋环境数据样本规模相对有限，系统采用迁移学习策略完成模型训练。首先加载 COCO 数据集预训练权重作为网络初始化参数，然后利用构建完成的涡旋实例分割数据集进行监督训练。虽然海洋环境场与自然图像在数据形式上存在差异，但预训练模型在低层卷积阶段学习到的边缘、纹理以及局部空间结构特征具有一定通用性，因此能够加快模型收敛速度，提高训练稳定性。

### 5.3.2 OW引导的代理学习机制

传统 Okubo–Weiss 方法能够依据海洋动力学规则直接识别涡旋区域，但其运行过程需要持续计算流速梯度、相对涡度以及应变率等动力学参数，并依赖阈值分割完成候选区域提取。当分析区域范围较大或需要连续处理长时间序列数据时，相关计算过程会带来较高的计算开销。同时，OW 方法对阈值设置具有一定敏感性，在复杂海况背景下容易受到局部噪声干扰。

为提高系统运行效率，本文采用“OW规则生成伪标签—实例分割模型学习”的方式构建涡旋识别框架。训练阶段利用 OW 动力学规则自动生成实例分割标签，作为模型监督信号；推理阶段则利用训练完成的 YOLOv8-seg 模型直接完成 ADT 场到涡旋区域的映射，从而实现由动力学规则驱动识别向数据驱动推理的转换。

在模型训练过程中，输入数据为经过归一化处理后的 ADT 图像，监督信息为 OW 规则生成的实例分割标签。通过大量样本学习，模型逐步建立海表动力高度空间结构与涡旋边界之间的对应关系，使海洋动力学规则所蕴含的空间特征知识能够迁移至深度学习模型参数之中。

从实现机制上看，OW 方法与 YOLOv8-seg 在系统中承担不同角色。OW 方法本质上属于基于物理规则的自动标注器，其主要作用是在缺乏人工标注样本条件下生成训练标签；YOLOv8-seg 则属于代理学习模型，其任务是学习海表动力高度场与涡旋区域之间的映射关系，并在运行阶段代替传统动力学计算过程完成目标识别。

因此，本文构建的代理学习框架本质上是一种“离线规则标注、在线快速推理”的混合模式。这实现方式与近年来弱监督学习利用伪标签构建监督信号的研究思路具有一致性[33,34]。该方法既保留了 OW 动力学判据的物理可解释性，又充分发挥了深度学习模型在推理效率和抗噪能力方面的优势，为海洋中尺度涡旋自动识别提供了一种兼顾识别精度与工程部署能力的实现方案。

图5-1展示了传统OW规则识别流程与YOLOv8-seg代理推理流程之间的差异。可以看出，OW方法需要依赖地转流速场，并经过空间梯度计算、相对涡度计算、应变率计算、OW参数构建、阈值判定以及连通域后处理等多个步骤，对阈值设置和数据质量具有一定敏感性。

5.4 风浪异常双轨预测模块的实现

为了实现海洋风浪变化趋势监测、异常识别与辅助解释，系统设计了风浪异常分析模块。模块以双头LSTM预测模型为核心，通过风速和有效波高预测结果构建异常检测机制，并结合历史风过程库完成异常过程的辅助解释。该模块主要包括两条分析链路：第一条链路利用 WindWaveLSTM 模型对风速和有效波高进行趋势预测，并基于观测值与预测值之间的残差判断是否存在异常；第二条链路在异常发生后，利用DTW方法对历史风过程候选事件进行相似度重排，从而为异常过程提供解释性参考。

DTW 查询侧采用异常窗内区域平均风速观测序列；历史侧为 IBTrACS 中心风速轨迹 wind_track_mps。anomaly_index 仅用于 3σ 异常分级与前端色带，不参与 DTW 距离计算。

### 5.4.1 滑动窗口时序重构

原始风浪数据以连续时间序列形式存储，而 LSTM 模型需要固定长度的输入样本。因此，系统首先采用滑动窗口机制将连续观测序列重构为模型可处理的三维张量。

系统从 NetCDF 文件中提取风速与有效波高序列，形成形状为 T×2 的输入特征矩阵。其中，T 表示时间步数量，2 表示风速和波高两个特征变量。根据系统配置，风浪预测模块采用 48 小时历史窗口，数据时间分辨率为 3 小时，因此一个输入窗口包含 16 个时间步。为了完成一步预测，系统至少需要 17 个时间步，即前 16 个时间步作为输入，第 17 个时间步作为预测目标。

### 6.1.3 数据集组成与切分方式

数据集包含海表动力高度（ADT）、风速以及有效波高等变量。在数据预处理阶段，系统首先对原始 NetCDF 数据进行变量统一、空间裁剪和时间切片，并进一步生成适用于模型训练的输入样本。

对于涡旋识别任务，系统采用基于 Okubo–Weiss（OW）动力学规则生成的伪标签掩膜作为训练标注[2,3]。数据集按照命题方提供的 NetCDF 文件进行划分，训练集由1993—2022年期间的3个训练文件组成，测试集采用2023年独立文件，验证集采用2024年独立文件。该划分方式在文件级实现训练、验证与测试数据隔离，避免了样本泄漏问题，同时保证了不同年份数据上的泛化能力评估。

为验证不同输入方案的影响，本文在模型开发阶段额外进行了消融实验。该实验仅从训练集中选取2018年样本构建训练子集，并继续使用2024年验证集进行评估，以考察模型在跨年份场景下的泛化能力。系统线上默认加载 ADT×3通道训练的权重，在后文中称为Fair-B0 ；表6-1 报告该部署配置在 2024 val / 2023 test 上的指标。数据集划分为 train 1993–2022，2019–2023 年样本包含于训练 NC，并非舍弃。

考虑到海洋环境存在年际变化特征，跨年份评估可能带来一定程度的域偏移（Domain Shift）。为减弱不同年份数据分布差异对模型训练的影响，本文采用统一的数据来源、固定的 OW 伪标签生成规则以及一致的数据预处理流程，并对输入变量执行基于分位数的归一化处理，以提高模型在不同年份数据上的适应能力。

对于风浪预测任务，采用时间顺序切分方式构建训练集、验证集和测试集，（train 2014–2023，test 2024，val 2025）以避免时间序列任务中的未来信息泄漏问题。系统以连续时间窗口构造训练样本，保证模型训练过程符合实际业务场景中的时序预测需求。

# 第7章 总结与展望

7.1 项目工作总结

本文围绕海洋环境智能监测场景，设计并实现了一套面向多维海洋数据的涡旋识别与风浪预警系统。系统以海洋观测数据自动处理、海洋中尺度涡旋识别以及风浪异常预警为核心任务，实现了从数据接入、智能分析到结果展示的完整业务流程。

系统以海洋中尺度涡旋识别与风浪异常预测为核心任务，结合深度学习模型、海洋物理规则以及可视化交互平台，实现了从海洋数据输入到智能分析结果输出的完整业务流程。

相比传统仅关注单一算法精度的研究方式，本文更加注重系统工程化实现与业务闭环构建。整个项目围绕软件系统开发流程展开，在需求分析、系统设计、模块实现以及系统测试等多个阶段完成了对应工作。

在系统需求分析阶段，本文结合海洋环境监测业务场景，对系统功能需求与非功能需求进行了分析。针对海洋数据来源复杂、变量结构不统一以及传统分析流程依赖人工处理等问题，提出了面向海洋智能分析场景的系统化解决方案。

在系统总体设计阶段，本文采用分层式系统架构设计思路，将系统划分为数据资源层、数据处理层、智能分析层以及应用展示层。通过统一的数据接口与模块解耦机制，实现了不同功能模块之间的协同运行。

在数据链路实现部分，系统完成了 NetCDF 数据自动解析、变量映射、时空切片以及模型输入构建等功能。针对不同海洋数据源变量命名不一致的问题，系统建立了统一变量字典映射机制，从而提高了多源数据兼容能力。

在涡旋识别模块中，本文基于 YOLOv8-seg 实例分割网络实现海洋中尺度涡旋自动识别。系统利用海表动力高度数据构建模型输入，并结合 OW 物理规则自动生成训练伪标签，实现海洋中尺度涡旋区域的自动检测与边界提取。基于海表动力高度场的实例分割方法能够有效学习 OW 动力学规则所表征的涡旋空间结构特征，在保持较高识别精度的同时，实现了从规则诊断到智能识别的自动化转换。

在模型训练数据构建阶段，系统进一步结合 Okubo-Weiss（OW）物理规则实现伪标签自动生成。相比人工逐帧标注方式，基于物理规则的自动化标注方法能够有效降低数据构建成本，并提高海洋场景下的数据处理效率。

在风浪异常预测模块中，本文采用共享编码器与双头回归结构的 LSTM 模型，对未来风速与浪高变化趋势进行联合预测。该结构能够在共享时序特征的基础上，同时完成多变量预测任务。

此外，为增强异常分析结果的可解释性，系统进一步引入 DTW 时间序列匹配方法，并构建历史风过程库。系统利用异常窗内区域平均风速观测序列与历史风过程进行相似性匹配，为当前异常过程提供辅助解释信息。DTW 模块仅作为异常分析的辅助工具，不参与风浪预测和异常等级判定。

在系统交互平台实现方面，本文采用 React 与 FastAPI 构建前后端分离式可视化分析平台，实现了数据上传、参数配置、模型推理调度、结果展示以及分析报告导出等功能。系统支持海洋环境场展示、涡旋识别结果展示、风浪趋势预测以及异常事件分析结果展示，能够较完整地呈现海洋环境智能分析过程。

在系统测试阶段，本文分别对智能算法模块与整体业务流程进行了测试。测试结果表明，系统能够较稳定地完成海洋环境数据处理、模型推理以及结果展示等任务。在涡旋识别与风浪预测任务中，系统均取得了较好的运行效果，并能够完成完整分析流程。

总体来看，本文完成了一套面向海洋环境智能分析场景的系统设计与工程实现，验证了深度学习方法在海洋环境监测领域中的应用可行性，同时也为后续海洋智能分析平台研究提供了一定参考。

7.2 系统局限性与未来展望

尽管本文完成了基于 NetCDF 多源海洋数据的海洋环境智能监测系统设计与实现，并实现了海洋中尺度涡旋识别、风浪异常预测以及历史事件关联分析等功能，但受数据来源、实验条件以及研究周期等因素影响，系统仍存在一定局限性，后续仍具有进一步完善和扩展的空间。

### 7.2.1 实时海洋数据接入能力提升

当前系统主要面向离线 NetCDF 数据分析场景，用户需要预先获取海洋环境数据文件后再进行分析处理。

在实际海洋监测业务中，环境数据通常以连续流形式实时产生，因此未来可进一步接入海洋观测浮标、卫星遥感平台以及海洋再分析服务接口，实现实时数据自动获取与更新。

通过构建实时数据接入机制，系统能够从离线分析平台逐步扩展为实时海洋环境监测平台，提高系统实际应用价值。

### 7.2.2 历史风过程库扩展

目前系统历史关联分析模块主要基于已有历史风过程库完成 DTW 相似性检索。受样本规模限制，部分异常过程可能缺少足够相似的历史参考案例。未来可进一步扩充不同海域、不同季节以及不同天气背景下的风过程样本，提高异常解释结果的参考价值。

未来可进一步扩充历史台风事件、强风浪过程以及其他极端海洋事件样本库，并建立更加完善的历史事件管理机制，提高异常分析结果的可靠性和参考价值。

同时，可结合更多环境变量参与相似度计算，使历史案例检索结果更加符合实际海洋环境变化规律。

### 7.2.3 长时间尺度风浪预测优化

本文采用双头 LSTM 网络完成风速与浪高联合预测，在短期预测任务中取得了较好的效果。

然而随着预测时间窗口不断增加，时间序列误差会逐步累积，从而影响长期预测结果的准确性。

未来可进一步扩充训练样本规模，优化窗口构造策略与异常检测机制，并探索多步预测能力，提高系统对长时间尺度风浪变化过程的刻画能力。

综上所述，未来系统将在实时数据接入、历史事件知识库建设以及长时间尺度预测能力提升等方面持续优化，不断提高海洋环境智能监测与辅助决策能力
