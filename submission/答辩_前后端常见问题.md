# 答辩常见问题：前端与后端

> 依据本仓库 **React + FastAPI + `src/`** 实际实现整理，供毕设答辩准备。  
> 代码入口：`web/`、`web_api/`、`src/anomaly/detect.py`、`src/eddy/`、`app/config/demo.yaml`

---

## 一、前端（React + Vite）

### 1. 架构与选型

**Q1：为什么用 React + FastAPI，而不是只用 Streamlit？**

- 论文演示系统采用 **前后端分离**：React 负责交互与可视化，FastAPI 负责 NC 解析与模型推理。
- Streamlit（`app/`）保留作实验/内部演示；答辩主界面是 **React 四顶栏任务页**（监测总览 / 涡旋分析 / 风浪分析 / 报告管理）。
- React 组件化适合「左配置—中场图/曲线—右统计」布局；Vite 开发热更新快。

**Q2：前端如何调用后端？有没有统一封装？**

- `web/src/adapters/*Adapter.ts` 封装 `fetch`；基址在 `apiBase.ts`（环境变量 `VITE_API_BASE` 或开发代理 `/api`）。
- 页面组件（如 `EddyPanel`、`WindWaveForecastChart`）**只 import adapter**，不在 UI 里硬编码 URL。

**Q3：离线模式和实时模式在前端怎么区分？**

- 路由：`/offline`、`/realtime`；`offlineSession`、`DataSourceBar` 管理数据源状态。
- **离线**：用户上传 NC → 预处理/推理；**实时**：轮询 `GET /api/realtime/latest` 获取目录中最新的 NC。

**Q4：为什么论文界面是四个顶栏入口，而不是一块三栏大屏？**

- 对齐论文 §4.5：**按任务拆分**（涡旋、风浪、报告），避免单页信息过载。
- 每页采用 **左（TaskConfigPanel）— 中（场图/曲线）— 右（统计/Top-K/导出）**，便于截图写入论文系统章。

### 2. 涡旋模块展示

**Q5：涡旋识别结果在前端怎么展示？**

- `EddyPanel` / `EddyAnalysisPage`：ADT 场图、实例掩膜、时间索引、统计表；可选双 MP4 动画。
- 数据来自 `eddyDualMp4Adapter.ts`、`eddyPreviewAdapter.ts` → `POST /api/eddy/preview-frame`、`/api/eddy/dual-mp4` 等。

**Q6：推理输入是几通道？界面上有没有 7 通道？**

- **论文与答辩演示默认 3 通道**（ADT + u + v），与 `config/eddy.yaml` 及权重一致。
- 7 通道为 **消融实验**（见 `submission/tables/eddy_ablation_*`），**不是** React 演示路径默认入口。

**Q7：双 MP4 是什么？推理慢怎么办？**

- 双路 MP4 分别展示输入场与分割掩膜，便于答辩演示连续时序。
- 长耗时任务可走 **异步 job**（`jobAdapter.ts` + `POST /api/jobs`），前端轮询进度，避免 HTTP 长时间阻塞。

---

### 3. 风浪预测与异常展示

**Q8：风浪曲线图画了几条线？异常等级怎么显示？**

- **四条曲线**：风速观测/预测、波高观测/预测（`WindWaveForecastChart.tsx`）。
- **背景色带**来自逐步 `anomaly_segments[].level`（normal/low/medium/high → 无/黄/橙/红）。
- **不绘制** `current_curve`（有量纲，非正式分级依据）。
- 右栏或标题区展示全局 `anomaly_level`、`anomaly_index`（来自 `compute_anomaly_assessment`）。

**Q9：Top-K 台风候选在前端哪里看？显示什么？**

- `WindwaveAnalysisPage` / `WindWaveLevel1View` 右栏 `TopKCard`：排名、`event_id`、初筛 `score`、`dtw_distance`。
- `typhoonDtwUi.tsx` 展示 DTW 元数据：异常时段、`dtw.window`、match_mode、是否 fallback。

**Q10：用户从上传到看到结果的典型步骤？**

1. 左栏 `TaskConfigPanel`：上传 NC、选择 time_start/end、bbox、任务类型  
2. `preprocessAdapter` → `POST /api/preprocess/subset`（可选）  
3. 风浪：`windwaveForecastAdapter` → `POST /api/windwave/forecast`  
4. 中场：`WindWaveForecastChart` 四线 + 色带；右栏 Top-K + 等级  
5. `reportAdapter` → `POST /api/report/structured` 导出 Markdown/结构化报告

### 4. 工程与体验

**Q11：跨域 CORS 怎么处理？**

- 开发：Vite dev server 代理 `/api`，或 FastAPI 允许 `http://127.0.0.1:5173`。
- 生产：构建产物 `web/dist` 与 API 同源部署，或通过 `VITE_API_BASE` 指向后端域名并配置 CORS。

**Q12：后端不可用时前端如何提示？**

- `apiBase.ts` 中 `formatApiFetchError` 捕获 `TypeError`（连接失败）并提示启动 `scripts/run_web_api.ps1`。
- 可选 `pingApiHealth()` 检查 `GET /api/health`。

**Q13：TypeScript 类型与后端 JSON 如何对齐？**

- 各 adapter 导出类型：`WindwaveSeriesPoint`、`AnomalySegment`、`TyphoonCandidate` 等（`windwaveForecastAdapter.ts`）。
- 与 OpenAPI（`/docs`）字段名保持一致，减少联调歧义。

**Q14：为什么答辩不主打水文热力图？**

- 论文系统章叙事为 **涡旋识别 + 风浪异常**；水文 ConvLSTM 为扩展模块。
- `VITE_SHOW_HYDRO` / `SHOW_HYDRO_UI` **默认关闭**；开启后才有 `HydroPanel`、 `/l1/hydro`。

**Q15：台风知识库有独立页面吗？**

- 有 `TyphoonKbPage.tsx` / `TyphoonKbPanel.tsx`，调用 `typhoonKbAdapter` → `POST /api/typhoon-kb/query`。
- 风浪任务页右栏也 **内嵌 Top-K**，减少跳转。

## 二、后端（FastAPI + `src/`）

### 1. 总体架构

**Q1：后端如何分层？**

| 层 | 路径 | 职责 |
|----|------|------|
| HTTP | `web_api/routers/*.py` | 路由、Pydantic 校验、组装 JSON |
| 算法 | `src/eddy/`、`src/anomaly/`、`src/preprocess/` | 训练/推理/检测 |
| 配置 | `config/*.yaml`、`app/config/demo.yaml` | 超参、路径、台风/D TW 口径 |

Router 保持 **薄封装**：复杂逻辑在 `src/`，不在 router 内重复实现。

**Q2：主要 REST 接口有哪些？**

| 模块 | 接口 | Router |
|------|------|--------|
| 健康检查 | `GET /api/health` | `health.py` |
| 预处理 | `POST /api/preprocess/subset` | `preprocess.py` |
| 涡旋 | `POST /api/eddy/preview-frame`、`/dual-mp4` | `eddy_dual.py` |
| 风浪 | `POST /api/windwave/forecast` | `windwave_report.py` |
| 台风 KB | `POST /api/typhoon-kb/query` | `typhoon_kb.py` |
| 报告 | `POST /api/report/structured` | `report.py` |
| 异步任务 | `POST /api/jobs`、`GET /api/jobs/{id}` | `jobs.py` |
| 离线 NC 上传 | `POST /api/offline/nc` | `offline_nc.py` |
| 实时轮询 | `GET /api/realtime/latest` | `realtime_nc.py` |

**Q3：为什么 Python 包名是 `web_api`？**

- 避免与 Streamlit 应用内 `from services import …`（`app/services`）命名冲突（见 `web_api/README.md`）。

**Q4：启动命令？**

```bash
python -m uvicorn web_api.main:app --reload --host 0.0.0.0 --port 8000
```

前端开发：`cd web && npm run dev`（默认 5173）。

### 2. 数据与预处理

**Q5：NetCDF 如何解析？大文件如何避免 OOM？**

- **xarray** 打开 NC，结合 **懒加载 / 按块读取**（`src/preprocess/nc_lazy_subset.py`）。
- 先按用户 **time + bbox 子集**，再进入涡旋/风浪 pipeline，避免整文件进内存。

**Q6：不同产品变量名不一致怎么办？**

- `config/nc_variable_map.yaml` 将 `adt/sla/u10/swh` 等别名映射到内部标准名（论文表 5-1）。
- 预处理 API 返回 meta，供前端与后续模块统一字段。

---

### 3. 涡旋识别

**Q7：在线为什么不用 OW 全图实时计算？**

- **训练期**：OW 规则 + 后处理 → **伪标签** → YOLOv8-seg 监督训练。
- **在线期**：3 通道场图 → YOLOv8-seg 推理 → 掩膜，作为 OW 判别链的 **代理模型**，减少梯度/OW 在线开销。

**Q8：涡旋评测指标？**

- 以 **mAP** 等 detection/segmentation 指标为主；具体数值见 `submission/tables/eddy_map_val_test.md` 及云端训练日志。
- **不可擅自修改** eval 输出字段与 `config level` 语义（项目规范）。

---

### 4. 风浪 LSTM 与异常检测

**Q9：`WindWaveLSTM` 结构？**

- 共享 `nn.LSTM(in=2, hidden=128)`，末步隐状态 → `wind_head` / `wave_head` 两个 `Linear(1)`。
- 输入 `(B, T, 2)` 区域平均风+浪；输出 `(B, 2)` **下一步**预测。
- 定义见 `src/anomaly/model.py`；在线滑窗见 `src/anomaly/inference.py` → `rolling_predict`。

**Q10：滑窗参数？**

- `config/anomaly.yaml`：`window_hours=48`，步长来自 `config/data.yaml` 的 `time_step_hours`（通常 3h → 16 步）。
- `horizon_hours=1` → 预测 1 个 time step ahead。

**Q11：异常指数 `anomaly_index` 怎么算？与 `current_curve` 区别？**

- 逐步：`anomaly_index = 0.5·|z(wind残差)| + 0.5·|z(wave残差)|`，其中 z 的 σ 为 **整段序列** `std(观测−预测)`（下限 0.05 m/s、0.02 m），均值取 **0**。
- 等级：≥1 low，≥2 medium，≥3 high（`detect.py` → `_level_from_index`）。
- **`current_curve = |Δwind|+|Δwave|`** 用于涡旋演示 timeline 等兼容路径；**正式分级与前端色带以 `anomaly_index` 为准**。

**Q12：缺 LSTM 权重时怎么办？**

- `predict_wind_wave_from_series` 检测不到 `outputs/anomaly/best.pt` 或序列过短时，降级 **`smooth_baseline`（3 点平滑）**，并设置 `prediction_backend=smooth_fallback`，避免 silent 失败。

### 5. 异常事件窗、DTW 与 Top-K

**Q13：Top-K 完整链路？**

```text
anomaly_result（历史检索 start/end + bbox）
  → query_typhoon_events（时间硬筛 + bbox 硬筛 + score 粗排）
  → 取 Top-(3K) 条
  → build_wind_dtw_query_curve（异常窗内 wind_observed 切片）
  → rerank_candidates_by_dtw（z-score DTW）
  → 返回 Top-K（按 dtw_distance 升序）
```

入口：`link_anomaly_to_typhoon`（`detect.py`）。

**Q14：初筛 `score` 怎么算？**

- 当前默认 **`score = bbox_ratio`**（查询框被轨迹外包框覆盖的比例），配置 `app/config/demo.yaml` → `prescreen_score_mode: bbox_ratio`。
- 可选 `center_distance`：`score = 1 / 中心距(度)`。
- **已移除**「台风持续时间 + 24×bbox」旧公式；`time_overlap_hours` 仍写入候选 JSON 作诊断，**不参与 score**。

**Q15：历史台风与「当前时刻」时间不重叠，如何检索？**

- 检索 query 的 `start_time/end_time` 来自 **`history_search_mode: full`**（约 1945～今），**不是** NC 异常那几天的窄窗。
- `anomaly_start_time/end_time` 仅用于 **DTW 切曲线** 与前端展示。
- 语义是 **「在历史库中找形态相近的过程」**，不是「找同一时刻并发的台风」。

**Q16：DTW 是否参与 3σ 异常判定？**

- **不参与**。DTW 仅对已通过 bbox 初筛的候选做 **弱关联重排**；异常分级在 LSTM 残差 → `anomaly_index` 链上完成。

**Q17：DTW 查询曲线与候选曲线分别是什么？**

| 侧 | 内容 |
|----|------|
| 查询 | 异常事件窗内 **区域平均观测风速**（`regional_mean_obs_vs_ibtracs_center`） |
| 候选 | IBTrACS **中心风速过程** `wind_track_mps` |
| 匹配 | 两侧 **z-score 后 DTW**（比形态，不比绝对风速） |

**Q18：异常事件窗怎么提取？**

- `extract_primary_anomaly_window`：逐步 `anomaly_index ≥ τ`（默认 τ=1.5）的连续段；无则 **peak_centered** fallback；再 **pad=4**（边界 clamp，不补值）。
- 配置见 `demo.yaml` 的 `dtw_window_*`。

**Q19：bbox 通过的候选不足 30 条会怎样？**

- `query_typhoon_events(..., top_k=30)` 返回 **实际条数 N**（N≤30），**不凑数**。
- DTW 对 N 条重排，最终 **`min(N, K)`** 条；N=0 → `linked=False`。

### 6. 报告、异步与部署

**Q20：结构化报告包含什么？**

- `POST /api/report/structured`：汇总异常等级、风浪曲线摘要、Top-K 台风、涡旋统计等 → Markdown/JSON 字段，供 `/reports` 页导出。

**Q21：长耗时任务如何处理？**

- `web_api/job_queue.py` + `jobs.py`：windwave_forecast、eddy dual-mp4 等可异步执行；前端 `jobAdapter` 轮询状态。

**Q22：路径为何都用相对仓库根？**

- 规范要求：`resolve_path` + config 相对路径；禁止写死本机绝对路径；云端产物以训练日志为准溯源。

**Q23：React 与 Streamlit 是否共用模型？**

- **共用 `src/` 推理与检测代码**；HTTP 仅 React 走 `web_api`，Streamlit 走 `app/pages` + `app/services` 直调。

## 三、连环追问与标准答法

| 老师可能追问 | 建议回答要点 |
|--------------|--------------|
| **创新点是什么？** | ① OW 伪标签 + YOLOv8-seg 代理在线推理；② NetCDF 一体化 Web 闭环；③ 双头 LSTM + 无量纲异常指数 + 异常窗 + DTW 弱关联；④（可选）IBTrACS 过程库检索 |
| **最大局限？** | DTW 区域平均风 vs 中心风尺度不一致；Top-K 为形态参照非因果认定；LSTM 单步预测；表 6-3 为 Oracle 链路完成率非端到端台风检测 |
| **表 6-2 / 6-3 说明什么？** | 6-2：风浪 MAE/RMSE；6-3：历史风过程条数 + 检索/DTW **可跑通率**（合成/Oracle 查询条件下） |
| **为什么不用残差做 DTW？** | 旧口径 `\|obs−pred\|` 与 IBTrACS 中心风物理错位；现改为异常窗 **观测风过程** vs 历史 **中心风过程** |
| **full 模式下 overlap_h 有何用？** | 仅作 **lookback 裁年** 硬门槛；full 宽窗下近似台风生命史长度，**初筛排序已改为 bbox_ratio** |
| **老师问水文/ConvLSTM？** | 仓库有 `src/hydro/` 扩展；**论文系统章主叙事为涡旋+风浪**，答辩 Demo 默认不展示水文大屏 |
