# 云端训练：目录自查、归档与复现命令

> 与根目录 [README.md](../README.md)、`相关文件/AI_DEV_REQUIREMENTS.md` 一致；冲突时以规范原文为准。

---

## 0. 路径约定（代码契约 vs 产物溯源）

**代码契约（仓库内保持不变）**

- **锚点**：**仓库根**（含 `config/`、`src/`）。配置里使用**相对仓库根**的路径，`resolve_path()` 在云机与本机语义一致。
- **禁止**：在提交的源码中硬编码某一台机器的 **`/root/...`、`C:\...`** 作为默认产物路径。
- **`config/eddy_enh.yaml` 一例**：`paths.output_dir: AutoDL/outputs/eddy_enh` → 在云机常为 **`/root/autodl-tmp/EddyFusion/AutoDL/outputs/eddy_enh/train`**（另加 `train.run_name`，默认 `train`）。请以当次训练中 **Ultralytics 打印的 `Results saved to ...`** 或日志中的保存路径为**权威**。

**产物溯源（避免误读本地目录）**

- 开发者常把 **`AutoDL/`** 下内容作为云机训练的**手动下载或同步离线副本**，本地子目录是否与云机 1:1 一致**不具有配置诊断意义**；不要根据「本机多了一个 `train`」「少了某一级」断言线上 `output_dir` 配错。
- 材料、复盘、issue 描述应引用：**云机日志中的绝对路径** + **所用 `config` 中的相对 `output_dir` / `run_name`**。

## 1. 仓库根目录结构（职责）

| 路径 | 职责 |
|------|------|
| `config/` | 各模块 YAML（数据路径、超参、`output_dir`）；云机训练前确认 `config/data.yaml` 的 `paths.raw_root` 与数据实际位置一致。 |
| `data/raw/` | 命题方或本地小样本原始数据（仓库内仅保留 `.gitkeep` 类占位，大文件不提交）。 |
| `data/processed/` | 预处理产物：`hydro/*.npz`、`eddy/`（含 `dataset.yaml` 等）、`anomaly/`、`stats/`；大文件默认不提交。 |
| `src/` | 训练/评估/预处理入口模块（`python -m src.*`）。 |
| `scripts/` | Shell 一键链路与工具脚本（`run_*_train.sh`、`run_hydro_isolated.sh`、`hydro_cloud_assessment.py` 等）。 |
| `outputs/` | 权重与训练日志：`outputs/hydro`、`outputs/eddy`、`outputs/anomaly` 在 `.gitignore` 中保留目录占位；**扩展实验目录** `outputs/hydro_l0`、`hydro_l1`、`hydro_l2` 整树被忽略（不向远程提交权重）。 |
| `submission/` | 对外材料占位：`figures/`、`tables/`；大图/视频/PDF 可能仍被 `.gitignore` 忽略，需按需取消或单独拷贝。 |
| `docs/` | 技术说明与本文档（可提交）。 |
| `app/` | Streamlit/演示；`app/data/eddy_preview/` 等为运行时生成预览，**.gitignore 已忽略**。 |
| `服创数据集/` | 命题方原始 NetCDF（默认名；可软链至数据盘）；不提交。 |

---

## 2. `.gitignore` 要点（云上同步时注意）

- 权重与大数据：`*.pt`、`*.npz`、`*.nc`、`*.npy`、`.zarr` 等全局忽略；`data/processed/*`、`outputs/*` 下内容大体不提交。
- **`outputs/hydro_l0`、`hydro_l1`、`hydro_l2` 未被单独「反忽略」**：它们仍属于被忽略的权重区，训练完需**人工下载/拷贝**回本地或大文件存储备份。
- 开发记录目录 `开发阶段文档/`、`相关文件/`、`AutoDL/` 等在忽略或本地挂载策略中按需处理，勿依赖其出现在裸 `git clone` 仓库里。

## 3. 云机环境最小步骤（仓库根 = `EddyFusion`）

1. `git clone` → `cd` 到仓库根。
2. `python -m venv .venv && source .venv/bin/activate`（Linux）。
3. 按 CUDA 版本安装 **PyTorch ≥2.5.1**（GPU），再：`pip install -U pip && pip install -r requirements.txt`。
4. 验证：`python -c "import torch; print(torch.__version__, torch.cuda.is_available())"`。
5. 命题方数据：仓库内 `服创数据集/` **或** 软链——见根 `README.md`「云服务器」小节与 `scripts/setup_fuchuang_to_data.sh`。

## 4. 训练入口与产物目录对照

### 4.1 水文 ConvLSTM（主配置）

```bash
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True   # 可选
python -m src.hydro.train --config config/hydro_hycom.yaml
```

- 配置内 `output_dir`: **`outputs/hydro`**
- 评估：`python -m src.hydro.eval --config config/hydro_hycom.yaml --ckpt outputs/hydro/best.pt`（无 `best.pt` 时试 `last.pt`）

### 4.2 水文创新隔离实验（L2 / L1 / L0）

```bash
bash scripts/run_hydro_isolated.sh l2   # → config/hydro_hycom_l2.yaml → outputs/hydro_l2/
bash scripts/run_hydro_isolated.sh l1   # → outputs/hydro_l1/
bash scripts/run_hydro_isolated.sh l0   # → outputs/hydro_l0/
```

每条脚本末尾会：`eval`（val + test）并调用 `python scripts/export_material_table.py`。

### 4.3 涡旋 YOLO-seg

```bash
bash scripts/run_eddy_train.sh
# 等价：check_eddy_ready.py + python -m src.eddy.train --config config/eddy.yaml
```

- 产物：**`outputs/eddy/`**（`best.pt` 等）

### 4.4 风浪异常（双头等）

```bash
bash scripts/run_anomaly_train.sh
# 等价：python -m src.anomaly.train --config config/anomaly.yaml
```

- 产物：**`outputs/anomaly/`**

## 5. 云端评估与归档（训练后）

| 步骤 | 命令 / 产物 |
|------|-------------|
| 水文预处理数据核查 | `python scripts/hydro_cloud_assessment.py audit --hydro-config <与训练一致的yaml> --data-config config/data.yaml --out-json <路径>/hydro_preprocess_audit.json` |
| L2/L1/L0 或基线权重对比 | `python scripts/hydro_cloud_assessment.py compare ...`（产出 `*_summary.json` 等；路径以脚本 `--help` 为准） |
| 全链路指标表刷新 | `bash scripts/run_eval_all.sh`（需各模块 checkpoint 就绪） |
| 企业材料用表 | `python scripts/export_material_table.py`、`submission/tables/*.csv`、`*.md` |

**建议从云机拷回本地的文件（命名可统一放入 `submission/tables/` 或团队约定的 `AutoDL/` 快照目录）：**

- `hydro_preprocess_audit.json`、`hydro_compare_*_summary.json`
- `outputs/*/metrics_summary*.json`（若有）
- 刷新后的 `submission/tables/*`
- 涡旋：`python scripts/collect_eddy_materials.py` 输出的图（若在云机运行）

本地仓库中：`docs/水文_L2L1L0_实验归档与决策.md`、`docs/后续开发工作清单_未完成项与云端L0专项.md` 与各清单应对照上述路径更新「最终口径」条目。
