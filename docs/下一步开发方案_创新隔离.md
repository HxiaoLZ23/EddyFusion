# 下一步开发方案（创新隔离版）

> 目标：在不破坏当前可交付结果（Level 2）的前提下推进创新；若创新收益不明显，项目最终保留 Level 2 结果提交。

## 1. 决策前提（已确认）

1. **台风知识库**：若需要人工标注/人工清洗才能构建高质量数据链路，则本阶段**不做该方案**。  
2. **水文创新栈**：采用“**与 Level 2 完全隔离**”策略推进 Level 1/0 实验，不覆盖当前稳定配置。  
3. **提交策略**：若创新收益不明显或稳定性下降，最终以 **Level 2** 作为默认交付版本。

---

## 2. 台风知识库范围约束

### 2.1 本阶段可做（自动化、低风险）

- 仅做**自动可复现**的数据流程（公开数据下载脚本、解析脚本、索引生成）。
- 可交付产物限定为：
  - 事件索引（JSON/CSV）
  - 自动统计报表
  - 与异常结果的弱关联展示（可选）

### 2.2 本阶段不做（人工依赖高）

- 人工标注台风事件窗口；
- 人工逐条清洗风浪记录；
- 依赖人工确认的事件级“真值构建”流程。

### 2.3 结论

- 若自动流程无法形成稳定可用数据，则台风知识库功能降为“后续扩展项”，不阻断当前交付。

---

## 3. 水文创新栈隔离策略（Level1/0 vs Level2）

### 3.1 隔离原则

- **配置隔离**：新增独立配置文件（建议）  
  - `config/hydro_hycom_l2.yaml`（当前稳定基线）  
  - `config/hydro_hycom_l1.yaml`（轻量创新）  
  - `config/hydro_hycom_l0.yaml`（全创新尝试）
- **产物隔离**：输出目录分开，避免覆盖  
  - `outputs/hydro_l2/`、`outputs/hydro_l1/`、`outputs/hydro_l0/`
- **评估隔离**：每条配置独立评估与表格行，不混写。

### 3.1.1 已落地执行入口（当前仓库）

- 一键脚本：`scripts/run_hydro_isolated.sh`
- 用法：
  - `bash scripts/run_hydro_isolated.sh l2`
  - `bash scripts/run_hydro_isolated.sh l1`
  - `bash scripts/run_hydro_isolated.sh l0`
- 行为：按所选 level 依次执行 `train -> eval(val) -> eval(test) -> export_material_table`，并写入独立目录 `outputs/hydro_l{2|1|0}/`。
- **已实现（L1）**：`mot.enabled=true` 时，`HydroMotCascade` 在 ConvLSTM 前加入时序双流门控 Stem；`loss.eos_constraint.enabled=true` 时在训练中叠加 T–S 残差耦合项（近似 EOS，z-score 空间）。参见 `src/hydro/mot_stem.py`、`src/hydro/losses.py`。
- **未实现**：`AttnRes`（L0）仍待接入 `build_model`；L2 仍为纯 ConvLSTM + MSE 训练损失。

### 3.2 实验推进顺序

1. 以当前 L2 为锚点（固定数据与随机种子）；
2. L1：仅加 1~2 个创新项（如 MoT-lite + EOS 小权重）；
3. L0：在 L1 稳定后再叠加（如 AttnRes）；
4. 每一步都与 L2 对照，不做跨版本混改。

### 3.3 回退规则（硬约束）

满足任一条件即判定“收益不明显”，回退并保留 L2：

- 指标无稳定提升（如连续多轮无明显改善）；
- 训练/评估稳定性显著下降（nan、不收敛、明显抖动）；
- 工程复杂度提升但无法转化为材料可解释增益。
