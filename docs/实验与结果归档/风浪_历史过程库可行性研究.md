# 历史风浪过程库 — 可行性研究

> **日期**：2026-06  
> **背景**：模块 C 台风弱关联层计划从「`peak_wind_kt` 常数线 + DTW」升级为「查询曲线 ↔ 历史 wind(t)/wave(t) 过程匹配」。本文评估数据、工程与答辩风险。  
> **结论摘要**：**不存在**一键下载的「台风风浪过程库」成品；**可构建**，建议 **三档路线**（IBTrACS 风轨迹 → 命题 NC 区域序列 → ERA5/CMEMS 再分析），与 LSTM 训练口径对齐时 **仅命题 NC 档完全同域**，再分析档需显式声明数据来源。

---

## 1. 目标定义

### 1.1 要建的是什么

对每个台风 `event_id`，持久化与 **模块 C LSTM 同语义** 的时序（推荐 3h 步长）：

| 字段 | 含义 | 与查询侧对齐 |
|------|------|--------------|
| `wind_series` | 区域平均 \|U10\| (m/s) 或等价 | 与 `pred_future[:,0]` / obs  wind 同量纲 |
| `wave_series` | 区域平均 SWH (m) | 与 `pred_future[:,1]` 同量纲 |
| `combo_curve` | `wind + wave` 或 \|Δwind\|+\|Δwave\|（需在文档固定） | DTW 输入 |
| `time_step_hours` | 3 | 与 `anomaly_preprocess.time_step_hours` 一致 |
| `source` | `proposition_nc` / `ibtracs_track` / `era5` | 答辩必写 |
| `coverage` | `full` / `wind_only` / `missing` | 是否可参与 DTW |

写入 `events.json` 扩展字段或 sidecar：`typhoon_kb/event_series/{event_id}.npz`。

### 1.2 不是什么

- **不是**现成商业/开源「Typhoon Wind-Wave Process DB」产品（无统一 API）。
- **不是** IBTrACS 当前索引（仅 metadata，见 `src/anomaly/typhoon_kb.py`）。
- **不能**与 Oracle 时空 Recall 混为「DTW 过程相似度已验收」。

## 2. 公开数据源盘点

### 2.1 无「成品过程库」

公开数据是 **组件**，需按 `event_id × 时段 × 空间` 自行抽取：

| 组件 | 提供什么 | 缺什么 |
|------|----------|--------|
| **IBTrACS** | 台风路径、多机构 WMO/USA/CMA **中心风速** (kt)，~3–6h | **无 SWH**；风是 **中心点** 非区域平均 |
| **ERA5** (CDS) | 1940–今，10m u/v、**significant height of combined wind waves**，可裁剪 bbox | 再分析，非命题 NC；台风极值可能平滑 |
| **CMEMS WAVERYS** | 1980–今，全球 SWH **3h**，1/5° | 需注册；与 ERA5 风场需自对齐 |
| **CMA 最佳路径** | 西北太平洋台风风圈/强度 | 格式不统一；**浪高通常无** |
| **浮标/卫星** | 点观测真值 | 稀疏，难覆盖每场台风全生命周期 |

### 2.2 与本项目最相关的两源

**A. 命题方「风-浪异常识别」NC（已在 `anomaly_dataset.py` 使用）**

- 路径：`服创数据集/风浪异常识别/{年}/{月}/` → `*oper*.nc` (u10/v10) + `*wave*.nc` (swh)
- 提取：`extract_wind_wave_from_month_dir` → 区域 **nanmean** → `(T,2)` **[|U10|, SWH]**
- **与 LSTM 训练/推理完全同口径**（理想历史侧）

**B. IBTrACS v04r01（本仓库已有 `data/raw/typhoon/ibtracs/`）**

- `build_typhoon_index` 已读逐点轨迹，但 **聚合后丢弃** `wind_kt(t)`，仅留 `peak_wind_kt`
- 改造量小：构建时追加 `wind_track_kt: [..]`（按 ISO_TIME 排序）
- **无 wave**；风为 **台风中心** 非海区平均

## 3. 覆盖率粗算（本机可复现）

### 3.1 研究海区（`config/data.yaml` → `spatial`）

`lon 117–127°E，lat 31.04–41°N`（与 LSTM 区域平均一致）。

### 3.2 IBTrACS × 海区 × 强度

脚本口径：轨迹 bbox 与海区相交、`peak_wind_kt ≥ 34`（热带风暴及以上）。

| 统计项 | 数量（本机 2026-06 扫 CSV） |
|--------|---------------------------|
| 全历史满足条件事件 | **396** |
| 与 **2014–2023**（LSTM 训练年）有交集 | **57** |
| 与 **2024**（test 年）有交集 | **5** |
| 轨迹点中位数 | **89** 点 |
| 过程时长中位数 | **~264 h**（~11 天） |

说明：Oracle 关联评测 **84/84（2024 全球过滤）** 与 **海区 5 场** 不是同一集合；过程库若绑海区，**2024 可建序列的事件远少于 84**。

### 3.3 命题 NC 覆盖（依赖本机数据）

- 训练划分：`anomaly_year_split` **2014–2023** + val 2025 + test 2024
- 本仓库开发机 **未必挂载** `服创数据集/风浪异常识别`；有数据时按月目录拼接，**仅覆盖命题提供年月**
- **预期**：对 57 个「海区 IBTrACS 事件 ∩ 2014–2023」，仅 **台风存续期落在已有 NC 月份内** 的可提取完整 wind+wave；过境但 NC 缺月 → **缺失或 partial**

### 3.4 再分析（ERA5 / WAVERYS）

- **时间**：ERA5 1940+；WAVERYS 1980+，**3h SWH** → 与项目步长一致
- **空间**：可按 **固定海区 bbox** 做区域平均（与 LSTM 一致），或沿 **台风路径逐点采样**（与 IBTrACS 一致，但与 LSTM 不一致）
- **代价**：CDS/API 下载、TB 级存储、批处理脚本；赛题答辩需说明 **非命题方原始数据**

## 4. 三档实现路线

### 档 1 — IBTrACS 风轨迹（最低配，1–2 人日）

**做法**：改 `build_typhoon_index`，对每个 event 持久化：

```json
"wind_track_kt": [35, 40, ...],
"track_times": ["2018-08-01 00:00:00", ...],
"series_source": "ibtracs_center_wind",
"wave_series": null
```

- 重采样到 **3h**（线性插值 + 对齐 UTC）
- `combo_curve` 暂用 `wind_track_kt` 转 m/s 或 kt 归一化；**wave 用 null 或 wind 复制（须标注 fallback）**

| 优点 | 缺点 |
|------|------|
| 数据已在库；实现快 | **无浪**；中心风 ≠ 区域平均；与 LSTM 语义不一致 |
| 84/84 全球事件均可给 **风形状** | DTW 仍是「弱过程」，答辩要说清 |

**可行性**：★★★★★（技术） / ★★☆☆☆（与 LSTM 同口径）

---

### 档 2 — 命题 NC 区域 wind+wave（推荐主档，3–7 人日）

**做法**：新脚本 `scripts/build_typhoon_event_windwave.py`：

1. 读 `events.json`（IBTrACS 事件窗 + bbox）
2. 对 `[start_time, end_time]` 与 **研究海区** 求交
3. 调用现有 `extract_wind_wave_from_month_dir` / 按日 NC 裁剪，拼接 `(T,2)`
4. 写入 `wind_series`, `wave_series`, `combo_curve=wind+wave`, `source=proposition_nc`

| 优点 | 缺点 |
|------|------|
| **与 LSTM 完全一致** | 覆盖 = NC 年月 ∩ 事件窗；**57/396 海区事件** 中仅部分有全序列 |
| 答辩可称「同域同变量」 | 2024 test 全球 84 场大多 **无 NC 序列** |

**可行性**：★★★★☆（有命题 NC 的机器） / 覆盖 ★★★☆☆

**建议 meta**：

```json
"coverage": "full|partial|missing",
"coverage_note": "NC months available: 2018-07,2018-08"
```

DTW 规则：`coverage != full` → **跳过 DTW，仅时空 Top-K**。

---

### 档 3 — ERA5 + WAVERYS 再分析（扩展/global 覆盖，1–2 周）

**做法**：

- 批量下载海区 `117–127, 31–41` 的 ERA5 `10m_u/v` + `swh`（或 CMEMS 3h SWH）
- 按 event 时间窗切片 → 区域平均 → 3h 序列
- 可选：对 **全球 84/84** 评测事件建库（不限海区）

| 优点 | 缺点 |
|------|------|
| 时间跨度长、事件覆盖高 | 下载/存储/算力；**非命题数据** |
| 风+浪齐全、3h 对齐 | 台风极值系统性偏低（文献常见） |

**可行性**：★★★☆☆（工程） / ★★★★☆（覆盖）

## 5. 对齐与 DTW 技术要点

| 问题 | 处理 |
|------|------|
| 查询 8 步 vs 历史 89 点 | DTW 天然支持不等长；固定 `query_len=8`（24h） |
| 离线 residual vs 在线 forecast 查询 | 过程库 **与查询曲线定义无关**；库侧始终是 **历史 obs 过程**（档2/3）或 **历史中心风**（档1） |
| 常数线退化 | 有序列则 **禁止** 走 `peak_wind_kt` 重复填充；无序列则 `dtw: disabled` |
| 单位 | 风 m/s、浪 m；IBTrACS kt → ×0.514444 |
| 存储 | 13544 事件 × ~100 点 × 2 float ≈ 数十 MB（可 sidecar npz） |

---

## 6. 与在线/离线叙事的关系

| 场景 | 查询曲线 | 历史库曲线 | 是否成立 |
|------|----------|------------|----------|
| 离线回放 + 未来残差 | `obs_future−pred_future` | 历史 **obs** 过程（档2/3） | ✅ 同语义（异常过程类比） |
| 在线预警 + forecast | `pred_wind+pred_wave` (8步) | 历史 **obs** 过程 | ✅ 需过程库；**预测 vs 历史实况** |
| 任意 | 任意 | `[peak_wind]*N` | ⚠️ 仅演示，不可写论文核心 |

过程库解决 **历史侧**；查询侧用 residual 还是 forecast 由 **有无 obs** 决定（见业务链路讨论）。

## 7. 风险与答辩话术

**风险**

1. **覆盖空洞**：全球 Oracle 84 场 ≠ 海区有 NC 序列的场数  
2. **档1 语义不一致**：中心风 vs 区域平均  
3. **再分析争议**：导师问「为何不用命题数据」  
4. **DTW 仍非 ground truth**：过程相似 ≠ 台风识别 POD  

**建议表述**

> 历史库为 **按事件对齐的风浪时序索引**，非开箱产品；优先用 **与 LSTM 同源的命题 NC 区域平均序列**；缺失时降级 **IBTrACS 风轨迹** 或 **禁用 DTW**；Oracle Recall 仅验证 **时空检索**，不验证 DTW 曲线质量。

## 8. 决策建议

| 阶段 | 动作 | 产出 |
|------|------|------|
| **P0** | 档1：IBTrACS `wind_track_kt` 写入 KB | 全事件 **风形状**；DTW 去掉常数线 |
| **P1** | 档2：命题 NC 抽 `wind_series/wave_series` | 海区 **57** 场量级 subset **full** 序列 |
| **P2** | 文档 + `coverage` 字段 + detect 降级 | 无序列不 DTW |
| **P3**（可选） | 档3 ERA5 补全球 2024 评测 | 表「过程库覆盖率」 |

**不推荐**：在未建库前，仅把查询侧改为 `forecast_curve` 而历史侧仍用 `peak_wind` 常数。
