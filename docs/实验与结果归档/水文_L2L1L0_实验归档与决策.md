# 水文 L2 / L1 / L0 三次训练归档与交付决策

本文档归档同套 **HYCOM 命题方预处理 npz、相同随机种子（config 中 `meta.seed: 42`）** 下三次隔离实验的结果，并说明 **是否采用创新栈（或部分采用）的理由**；最后归纳 **与赛题阈值仍有差距时的可能原因** 与 **改进方向**。

> **说明**：训练在云端路径如 `.../outputs/hydro_l{2,1,0}/` 下生成；下表指标来自各次 `metrics_summary_{val,test}.json` 与本仓库 `eval` 的 NRMSE 定义（通道 RMSE/|y| 均值再对通道平均）。日志中的 `val_nrmse` 为训练循环内的批聚合，与 **json 终值可能略有差异**，**以 json 为准**。

### 创新栈前基线（权威路径）

| 项目 | 说明 |
|------|------|
| **产物目录** | **`AutoDL/outputs/hydro/`**（相对仓库根；与云端 `.../EddyFusion/AutoDL/outputs/hydro/` 同步后一致） |

分项数值请以各目录下 **`metrics_summary_val.json`** 为准。下表为 **隔离实验** 对照用约数（**基线分项请看 `AutoDL/outputs/hydro/`**）。

| 要素 | 基线/L2 对照（约） | L1（约） | L0（约） |
|------|--------------------|----------|----------|
| temp | 0.070 | 0.082 | **0.071** |

## 2. 是否采用创新栈（或部分）的决策与理由

### 2.1 结论（推荐）

| 选项 | 建议 | 理由 |
|------|------|------|
| **主交付水文指标** | **优先采信 L0**（在可接受算力与可讲清前提下） | **val/test `nrmse_avg` 在隔离实验中最低**；分项上 **u/v 多略优于基线/L2**（以各 json 为准），与「全创新栈」叙事一致。 |
| **保守/简化交付** | **基线（`AutoDL/outputs/hydro`）或隔离 `hydro_l2`** | 结构最简单；与 **创新栈前** 叙述一致时用 **AutoDL** 路径最直观。 |
| **L1（仅 MoT + EOS + MAE，无 AttnRes）** | **不推荐作为主结果** | 在本批对照中 **整体 NRMSE 差于基线/L2**，说明当前权重与耦合项组合 **未形成净收益**；可作 **消融说明**。 |

### 2.2 若「仍要全文使用创新栈」的理由归纳

1. **指标**：L0 相对 **基线（`AutoDL/outputs/hydro`）/ 隔离 L2** 在 **整体 NRMSE 与 u/v 上**若有可量化提升（以各自 json 为准），不是纯叙事。  
2. **赛题/答辩**：可对应 **「时序混合（MoT-lite）+ 残差注意力（AttnRes）+ 物理近似约束（EOS）」** 的分层叙述。  
3. **隔离策略**：`hydro_l2 / hydro_l1 / hydro_l0` 输出目录分离，**不覆盖 `AutoDL/outputs/hydro` 基线备份**，评委追问时可对比 **基线 json vs L0 json**。

### 2.3 若「只采用部分创新」的合理说法

- **仅 MoT（不搞 AttnRes）**：当前 **L1 未优于 L2**，单独宣传「仅用 MoT」缺乏指标支撑，除非另做一轮 **超参/权重** 搜索后再评估。  
- **仅 AttnRes**：仓库未单独拆出「无 MoT 仅有 AttnRes」的配置；若需消融可再跑一次 **关 `mot.enabled`、开 `attn_res`** 的自定义 yaml（不在此表归档内）。  
- **仅 EOS/MAE**：已包含在 L1/L0 的训练损失中；单独关闭需改 config 做消融。

## 3. 「整体效果仍不理想」时的可能原因（相对赛题高阈值/期望）

此处的「差」指：**整体 NRMSE 仍在 ~0.81～0.84**，与材料中常见的 **「≤15%」类达标口径** 若按 **同维度 NRMSE** 理解，**差距仍大** —— 与 **分项结构** 与 **评测定义** 有关，并非单指 L0 无效。

1. **u / v 主导误差**  
   z-score 后若流场 **|y| 均值较小**，则 **NRMSE 分母小**，比值易被放大；模型在 **大尺度环流/锋面** 上仍难。  

2. **EOS 为 z-score 空间 T–S 残差耦合**  
   并非 **真实海水状态方程 + 现场压力**，仅起 **正则/多任务** 作用；权重不当会 **损害某一通道**（L1 曾出现 temp 略升）。  

3. **MoT / AttnRes 容量与数据**  
   参数量与优化难度上升，需 **学习率、权重、早停** 与之匹配；数据量或 **滑窗 stride** 不足时，复杂模块 **易欠拟合或仅边际增益**。  

4. **训练内 `val_nrmse` 与 eval json**  
   两路统计方式不完全相同，**应以 `eval` 输出写材料**，避免混用日志瞬时值与终值。  

5. **赛题原始指标口径**  
   若命题方对 **「15%」** 有 **单独 MSE/NRMSE 定义**（空间平均、变量加权等），需 **人工对齐**；本文档无法替代命题方评测脚本。

## 4. 可能的改进方向（在不破坏隔离的前提下）

| 方向 | 说明 |
|------|------|
| **按通道加权损失** | 对 u、v 提高 MSE 权重或与 NRMSE 对齐的加权，直接针对主误差源。 |
| **调 L1/L0 辅助损失** | 略降 `loss.eos_constraint.weight` 或 `mae_weight`，减少对 temp/sal 的挤压后再训，对照 L2。 |
| **AttnRes 瘦身** | 将 `attn_res.num_blocks` 从 8 降至 4～6，或略增 `reduction`，缓解过拟合与显存。 |
| **数据与滑窗** | 在 OOM 可控下 **更多日文件 / 合理 stride**，往往对流场帮助更大。 |
| **物理约束升级（工程量大）** | 若有 **反标准化系数**，可在 **物理空间** 加近似密度约束；需与预处理管道一致。 |
| **与命题方对齐评测** | 获取官方或样例评测代码，避免自建 NRMSE 与赛题表观「差一个数量级」的误解。 |
