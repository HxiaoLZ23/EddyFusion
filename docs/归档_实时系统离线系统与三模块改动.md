## 1. 信息架构与导航

**文件**：`app/main.py`

| 项 | 说明 |
|----|------|

## 2. 实时系统

**主文件**：`app/pages/realtime.py`  
**依赖**：`app/services/realtime_pipeline.py`、`services.inference_service`、OpenCV 采集。

| 能力 | 说明 |
|------|------|
| 数据源 | 摄像头 / RTSP / 上传视频（与既有推理服务衔接）。 |
| 运行态 | `RealtimePipeline` 限帧推理、`realtime_running` 与固定高度画面区，减轻布局抖动。 |
| RTSP | 失败时指数退避重连，`realtime_reconnect_attempts` / `realtime_next_retry_ts` 记录状态。 |
| 风浪演示 | 峰值分数与 `app/config/demo.yaml` 中 `realtime_windwave.peak_score_threshold`（及 mock 阈值回退）比较；**达标后由用户手动点击**生成 `run_detect` 与台风联动展示（非自动刷屏）。 |
| 联动缓存 | `realtime_windwave_linked` + `realtime_windwave_source_fp`，避免帧更新误刷新已生成的联动结果。 |
| 三模块同屏 | 页尾调用 `pages/ocean_tri_panel.render_tri_module_strip(mode_label=…)`，当前为**占位文案**（与离线系统共用组件）。 |

## 3. 离线系统

**主文件**：`app/pages/offline_system.py`

| 能力 | 说明 |
|------|------|
| 多文件 NC | `file_uploader` 多选 → `save_uploaded_nc` 落盘 → `cleanup_old_nc_uploads`。 |
| Facade 摘要 | 选择分支（涡旋 / 水文 / 风浪 / 全链路占位）→ `describe_for_branch` → JSON 摘要（**元数据级**，重型预处理仍走 `src/preprocess` 规划）。 |
| 逐文件探针 | `summarize_nc_file`：维度、变量列表、体积（`netCDF4` 只读打开）。 |
| **涡旋分支** | 选 NC + `time_index` + YOLO 路径/conf/iou/imgsz → `EddyDemoService.infer_netcdf_frame`，与「涡旋识别」页同款权重约定；结果含 `annotated_frame_bgr`、`geometries`、`meta`。 |
| 三模块同屏 | `render_tri_module_strip(mode_label="离线系统 · 本地上传 NC")`（占位）。 |
| 深链 | 页底文案引导至 **涡旋 / 水文 / 风浪预警** 单模块页做全功能。 |

## 5. 三模块工作台（与实时/离线的关系）

以下页面为 **单模块深链**，算法与数据契约仍是主线；实时/离线页是 **另一入口**，部分复用同一服务（如涡旋 `EddyDemoService`、风浪 `eddy_last_result` 会话）。

### 5.1 涡旋识别 — `app/pages/eddy.py`

- 视频 / NPZ / **NetCDF 路径①** 等入口合并在本页；成功推理写入 `st.session_state["eddy_last_result"]`（与风浪页共用键）。
- 含风浪要素的 NC 可合并 `wind_wave` 配套字段，供下游 `run_detect` 使用。
- **后续修补（2026-05-11）**：导出 MP4 默认 **FPS 由 6 改为 2**（滑块默认值，范围未改）。

### 5.2 水文推理 — `app/pages/hydro.py`

- **输入改为以 NetCDF 为主**：缓冲区 `hydro_nc_buffer` 追加上传文件 → FIFO 控制文件数 → `peek_hydro_buffer_time_steps` 估计 `T` → 满足 `T_need` 后 `materialize_netcdf_to_xy_npz` 构建临时 X/y NPZ 再推理。
- 与 `HydroInferenceService` 的缓冲、滑窗、`variable_map` 约定一致；页面内说明「步长不足不凑假窗」与实时兼容策略。
- 共用 `nc_ingest_service` 上传与清理。

### 5.3 风浪预警 — `app/pages/result.py` + `windwave_panel`

- 原「结果」页：**本页上传风浪 NC** 或沿用 **`eddy_last_result`**（涡旋页或本页最后一次成功写入为准）。
- `src/anomaly/windwave_nc_bridge.py`：`build_eddy_result_from_windwave_netcdf` 构建与配套 NPZ 同形字段，写入会话。
- 台风联动：`infer_typhoon_link_defaults_from_eddy_result` + `run_detect` + `render_typhoon_linked_outputs`。
- **后续修补（2026-05-11）**：  
  - `src/anomaly/eddy_typhoon_bridge.py`：优先根据 `meta.nc_path` 从 NC 读 **经纬度与时间** 推断联动检索框（外加 `demo.yaml` 的 query pad），时间解析失败则回退 `generated_at` 窗；  
  - `result.py`：`_typhoon_link_context_fingerprint` 在 **NC 路径 / 生成时间 / 来源类型** 变化时刷新 `ty_link_*` 会话，避免换文件后仍显示旧参数。

### 5.4 总览 — `app/pages/overview.py`

- 文案已对齐：**NC 摘要见「离线系统」**，**视频流见「实时系统」**，三模块指标摘要仍为只读展示。
